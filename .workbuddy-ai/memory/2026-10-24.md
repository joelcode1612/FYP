# 2026-10-24 (last) — ROOT CAUSE of the "port clash": it was the PROXY

## The misdiagnosis, corrected
For five sessions I treated the recurring `jaspr serve` failure as EADDRINUSE
from a stale server. That was **sometimes true but not the root cause**. The
decisive evidence: the user ran `jaspr serve -p 8099` — a port they explicitly
chose — and it still failed.

## Actual root cause: `HTTP_PROXY` set, `NO_PROXY` unset
```
HTTP_PROXY = http://127.0.0.1:59354
NO_PROXY   = <unset>
```
The user's own `flutter doctor` had been reporting this all along:
`[!] Proxy Configuration • HTTP_PROXY is set ! NO_PROXY is not set`.

Because `NO_PROXY` is unset, **every localhost request is routed through a proxy
that cannot reach it**. Symptoms:
1. Build daemon's WebSocket to `localhost:<random>` → **502**, aborting the
   build: `WebSocketException: ... was not upgraded to websocket, HTTP status 502`
2. A running server answering **500/502 on every path**, including static files
   (`/styles.css`, font files) — which is what made the old instance look
   "wedged"
3. Dart VM service failing to bind on 8181

**Fix:** `NO_PROXY=localhost,127.0.0.1,::1` — one line, fixes all three.
Verified: server started, VM service bound, `/`, `/admin/users`,
`/entrepreneur`, `/styles.css` all HTTP 200.

## How to tell the two apart in future
- **EADDRINUSE** → `netstat -ano | findstr :<port>` shows a LISTENING PID.
- **Proxy** → the port is FREE but you still get 500/502, and the build log shows
  a WebSocket 502. Check `echo %HTTP_PROXY%` / `echo %NO_PROXY%` FIRST — it is
  cheaper than the port hunt and explains strictly more symptoms.

## `serve.ps1` updated
Now sets `NO_PROXY`/`no_proxy` for the child process only (machine environment
untouched), and passes `-p $Port` through. Parses cleanly.

## Verified live
Server on 8099 serving the new design; `/styles.css` fetched over HTTP is
**byte-identical** to the local file. `/` 17,756 B · `/admin/users` 5,655 B ·
`/entrepreneur` 9,551 B · `/styles.css` 65,575 B.

## NEW FINDING — `API_BASE_URL` is inert
The user runs `jaspr serve --dart-define=API_BASE_URL=http://127.0.0.1:8080`.
`grep -rn "API_BASE_URL\|apiBaseUrl" fyp_jaspr_web/lib/` returns **nothing** —

# 2026-10-24 (final) — Third distinct failure mode: Jaspr's internal proxy port 5567

## New error, distinct from both earlier causes
```
Error: SocketException: ... port = 5567
#5  ProxyHelper.startProxy (jaspr_cli/src/helpers/proxy_helper.dart:107:20)
#6  DevCommand.runCommand       (jaspr_cli/src/commands/dev_command.dart:129:5)
```
`jaspr serve` (the **global CLI binary**) starts a local **dev proxy on a fixed
port 5567** before binding the user-facing port. The `dart run jaspr_cli:jaspr
serve` form does not take this path. So the failure is on 5567, not on `-p`.

## Diagnosis
Two separate `dartvm` processes were alive:
- PID 12252 → **5567** (the internal proxy), started 18:22:51
- PID 26532 → **8099** (the HTTP server), started 18:23:31

Both belong to one healthy `jaspr serve` the user had already started after the
NO_PROXY fix. The new invocation failed because **its own dev proxy could not
bind 5567**, which the running instance already held. The user-facing `-p 8099`
was never the problem.

## So: three distinct root causes across this project
1. **EADDRINUSE on the user port** — stale instance surviving console close
   (Windows does not SIGHUP the process group).
2. **HTTP_PROXY set / NO_PROXY unset** — localhost routed through an unreachable
   proxy; build-daemon WebSocket 502, server 500s on every path, VM service
   fails. Fixed with `NO_PROXY=localhost,127.0.0.1,::1`.
3. **EADDRINUSE on 5567** — Jaspr's *internal* dev-proxy port, held by an already
   running instance. Invisible unless you read the stack trace to
   `ProxyHelper.startProxy`.

## Verified the running instance serves the new design
- `/styles.css` over HTTP is **byte-identical** to the local file
- 6 `@font-face` rules served; `--paper`, `--shadow-sm`, `--radius-sm`,
  `--border-strong` all present
- Route smoke test, all HTTP 200: `/` 17,756 B · `/admin` 4,842 B ·
  `/admin/users` 5,655 B · `/admin/listings` 5,758 B · `/entrepreneur` 9,551 B ·
  `/entrepreneur/explore` 5,740 B · `/owner` 4,820 B ·
  `/owner/properties` 5,622 B · `/login` 4,936 B

## To restart cleanly
Kill **both** PIDs (the proxy holder and the server holder), or run `.\serve`,
which clears the user port. Note `.\serve` does **not** yet clear 5567 — a gap
worth closing if this recurs.

## `API_BASE_URL` still inert
`--dart-define=API_BASE_URL=http://127.0.0.1:8080` continues to do nothing:
`grep -rn "API_BASE_URL\|apiBaseUrl" fyp_jaspr_web/lib/` returns nothing. The
