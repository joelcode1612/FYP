## 360 checksum defect found in device run (2026-11-23)
- Screenshot failure "Your photos are safe" came from the new `_HandoffStatusScreen`, NOT a connection fault.
- Local DB proved full upload: session f78a22a4…/property 11896, 38 confirmed frames, 2 jobs; both jobs
  failed at "Downloading frames 1/38" with "Frame 1 failed its SHA-256 integrity check".
- ROOT CAUSE: my `File.openRead(64*1024)` treated the first positional arg as a chunk size; it is the START
  OFFSET. The coordinator hashed every JPEG from byte 65536 onward. Uploads used `openRead()` and were correct;
  Python hash of stored JPEG == Dart `sha256.convert` bytes, while old chunked code produced the bad digest.
- Fix: `openRead()` from byte 0 (no arg). Added in-place checksum repair: existing confirmed frames with a
  different digest are re-confirmed (no re-upload); FastAPI verifies stored bytes before accepting. If bytes
  genuinely differ (retake), it returns 409 and the coordinator starts a fresh session and uploads once.
- `flutter analyze` and backend py_compile clean after fix.
