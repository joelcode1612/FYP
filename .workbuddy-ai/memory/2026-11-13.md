## REVERSAL: management scoping turned OFF (same day, later)

The mandatory scoping described above is **wrong for this dataset** and has been
reverted. Measured against the live database:

    assigned catalogue ids : 227  (numeric ids: 101649242, ...)
    managed_only = false   : total = 290 rows
    managed_only = true    : total = 0   rows

Cause: `RecommendationManagementService._MAPPINGS_SQL` builds the manager map
only from `fyp.rental_properties` rows with `is_published AND
verification_status = 'approved'`. All 955 research-catalogue rows are
`pending`, so they never map, and the 227 mapped ids are numeric listing ids
that never intersect the `MD-…` / `EP-…` catalogue ids. The filter intersects
to nothing.

Fix: `recommendations_page.dart` now sends the DTO default
(`managedOnly: false`) from `_initialRequest`, `_apply`, `_applySort`,
`_applyRequest`, `_reset` and the cached-session rehydrate. `_empty(state)` was
restored to the general copy. The probe assertion flipped to
`managed_only === false`.

Rule for the future: never scope this page to managers unless the catalogue rows
themselves become approved+published. Re-run the two-line service measurement
above before touching it again.

## Why fixes "did not appear": the fixed-filename bundle was cached

Symptom: after the scoping fix the page still showed the OLD empty-state copy
("No assigned properties match"), even though that string was absent from both
`lib/` and `build/jaspr/main.client.dart.js`.

Cause: the app is served by **uvicorn**, not `tool/dev_static_server.js`
(`backend/src/sitewise/frontend.py` -> `mount_frontend`, registered last in
`main.py`). It sent `Cache-Control: no-store` for `index.html` but **no cache
header at all** for static assets, and `jaspr build` always writes the same
`main.client.dart.js`. The browser kept the previous bundle, so the shell
reloaded while old Dart kept running. `server: uvicorn` in the response headers
is the giveaway.

Fix: `frontend.py` now returns
`FileResponse(..., headers={"Cache-Control": "no-cache"})` for real files.
FileResponse already supplies an ETag, so an unchanged asset is a cheap 304 and
a rebuilt one is fetched immediately. Guard:
`backend/tests/test_frontend_cache_headers.py` (4 tests: bundle revalidates,
SPA fallback stays `no-store`, missing asset 404s, `/api/*` never returns HTML).

Second guard in `recommendations_page.dart` `initState`: if the session still
holds `managedOnly: true` (results cached from the scoped build), it is reset to
false and re-run once — otherwise the page is stranded on 0 results with no
visible control to clear it.

Operational note: a running uvicorn must be RESTARTED to pick up `frontend.py`
(it was started without `--reload`). Until then the old header persists and one
manual hard refresh is still needed.
