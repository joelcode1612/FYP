## Letter-reveal animation (scroll-triggered)
**Request:** "Letter Reveal when i scroll down the page can perform this animation"

**Implementation**
- `landing_page.dart`: new `_letterSpans(text, start)` renders `.lr-word` /
  `.lr-char` spans **in the component tree** (each char has `style="--i:N"`).
  Applied to the hero `h1` (split around its `<em>`, index continues) and the
  four `h2`s. Rendering spans in the VDOM keeps server/client DOM identical, so
  Jaspr hydration and `setState` reconciliation stay safe — do **not** split
  headings from JS after hydration.
- `web/reveal.js` (new): IntersectionObserver adds `.is-armed` then
  `.is-visible`; runs on `load` + 250 ms. Falls back to visible text if
  IntersectionObserver is missing, motion is reduced, or anything throws.
- `web/styles.css`: `@keyframes lr-char-in`; hero uses a time-based entrance
  (`backwards` fill); section headings transition from `.is-armed` to
  `.is-visible` with `transition-delay: calc(var(--i) * 14ms)`. Only opacity /
  transform / filter animate.
- `main.server.dart`: `<script src="reveal.js" defer>`.

**Why not `animation-timeline: view()`:** `.hero` and `.geo-explore-section`
use `overflow: hidden`, which makes `view()` resolve against those containers
instead of the document. Observer approach avoids that.

**Verified:** hero opacity 0→1; all 4 h2 arm then reveal; heading geometry
pixel-identical to plain text at 1440/1024/768/390; survives challenge-pill
`setState`; reduced-motion and no-JS show plain text; 0 verify_pages problems.

**Pre-existing bug fixed:** 4th challenge pill threw
`RangeError: index should be less than 3: 3` (blanked all sections) because
`_solutionDesc` had 3 entries while `_challenge` runs 0–3. Added a 4th entry.

**Mobile legibility fix (was broken on the first pass):** the hero was only
250 px tall, so the portrait SVG cropped to its bottom band and the buildings
scaled up behind the lead paragraph; the scrim was too weak and the road read
as a hard bar. Fixed: hero 380 px (≤1080) / 320 px (≤560); stacked-layout scrim
re-weighted to the top (`.95` → `.86` @38 % → `.6` @62 % → `.18` @88 %); art

fades out.
- **Lesson:** a portrait `viewBox` with `slice` crops to its *bottom* band in a

  container or re-weight the scrim rather than assuming `slice` shows
  everything.

**Build gotcha (new):** the Jaspr build daemon connects to a local
`ws://localhost:<port>` and the environment's `HTTP_PROXY` intercepts it →
`WebSocketException: Connection ... was not upgraded to websocket, HTTP status
code: 502`. Build with the proxy unset:
`env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy dart run
jaspr_cli:jaspr build` (deps are already cached, so no network is needed).

**Also note:** a background server started with a trailing `&` inside a Bash
tool call dies when that call returns. Use the tool's `run_in_background: true`
so the process is managed and stays alive.

- **Jaspr gotcha (important):** hydration syncs `input.checked` against an
  attribute value of exactly 'true' (`jaspr/client/dom_render_object.dart`).
  A raw `attributes: {'checked': 'checked'}` is read as false and silently
  UNCHECKED on hydration. Use the dedicated `input(checked: bool)` param.
- **jaspr_test gotchas:** `find.text(...)` resolves to a Text component and
  cannot be clicked (`_findDomElement` fails) — click via
  `find.ancestor(of: find.text(x), matching: find.tag('button'))`. There is
  no `find.byType('tag')` for strings (`byType` takes a Type); tag finder is
  `find.tag()`. Input events can't be simulated (handlers read
  `event.target`, null in the test binding) — filled-form behaviour must be
  probed in a real browser (`tool/probe_login.js`).
- Verified: `dart analyze lib test` clean, `dart format` clean,
  `dart test` 2/2 pass, `jaspr build` ok, `probe_login.js` all checks pass
  (incl. 0px overflow @1440+390, bg 1774x887 loads, checkbox default-on),
  `verify_pages.js` 62 routes 0 problems, signup + icon probes still pass.
