# 2026-10-14 (later still) — ROOT CAUSE of "UI not changed": a stale dev server

The user ran `dart run jaspr_cli:jaspr serve` and it **built successfully** but
failed to bind:

```
SocketException: ... errno = 10048, address = 0.0.0.0, port = 8090
```

`10048` is `EADDRINUSE`. `netstat -ano` showed **PID 28716 (`dartvm.exe`)
LISTENING on 0.0.0.0:8090**, with an established link to the VM service on 8181
(PID 33604, its child).

### Why this explains everything
An **older `jaspr serve` instance was still running and holding port 8090**. So:
- Every restart the user attempted **failed to bind**
- The old instance kept serving the **old built assets**
- The browser therefore showed the old UI, making it look like my icon / CSS
  changes had never been applied

Combined with the duplicate `.map-pin` block found in the same session, there
were **two independent reasons** the UI appeared unchanged, neither of which was
"the code is wrong".

### Fixed
`taskkill /PID 28716 /F` → *"SUCCESS: The process with PID 28716 has been
terminated."* PID 33604 had already exited with its parent. Ports 8090 and 8181
are now free (only `TIME_WAIT` entries remain, which clear themselves).

### Lesson to apply first, next time
**Before concluding a web change didn't take effect, check for a stale server
holding the port.** `netstat -ano | grep :8090` and look for a LISTENING pid. A
dev server that failed to rebind keeps serving stale assets and gives the exact
symptom of "my edits did nothing".

Also worth noting: `dart run jaspr_cli:jaspr serve` works as an alternative to
the globally-activated `jaspr.bat`, and resolves the workspace from the repo root.

# 2026-10-14 (final) — Explore panel restructured: list beside the map

User: *"put beside the map and when click the filter button the display
properties change to display input filter"*.

So the floating-overlay approach was wrong. Replaced with a **two-column layout**:

```
.explore__body            grid: 360px | 1fr
├── .explore__panel       LEFT — one slot, TWO MODES
│   ├── .explore__panel-head
│   └── .explore__panel-body
└── .explore__map-wrap    RIGHT — the map
    ├── .explore__map
    ├── .explore__detail  (floats over the map)
    └── .explore__zoom    (floats over the map)
```

- The panel shows the **property list** by default and **swaps to the filter
  inputs** when Filters is pressed — same frame either way, so the panel never
  resizes and the map never shifts.
- Implemented as `_listMode()` / `_filterMode()`, each returning `List<Component>`
  spread into the panel. Switching replaces the children only.
- The Filters button label now says which way it will switch (`Filters` ↔
  `Show list`), and it turns `primary` while the filter is open.
- Added a **Hide/Show panel** toggle so the map can take the full width
  (`.explore__body--full`).
- The detail card and zoom controls stay **floating over the map**, because they
  describe a point on the map rather than a row in the list.

Removed: `.explore__canvas`, `.explore__float*`, `.explore__list-head`,
`.explore__list-body`. Verified none remain in `lib/` or `web/`.

Responsive: 1100px narrows the panel to 300px and drops the detail card to the
bottom of the map; 900px stacks the columns with the map first (`order: -1`) and
caps the panel at 60vh.
