## Dart uri_does_not_exist root cause (2026-11-25)
- `listing_detail_page.dart:11` import of `features/property_verification/presentation/components/verification_detail_view.dart` failed although the file existed. Root cause: **three invalid UTF-8 bytes (0xB7, Windows-1252 middle dot) in the widget source**. The analyzer rejects invalid-UTF-8 libraries as import targets (uri_does_not_exist + creation_with_non_type) while `dart analyze <that file>` directly reports no issue. Repaired the 3 bytes to UTF-8 `·` (U+00B7); `dart analyze listing_detail_page.dart` now reports No issues. Rule of thumb: if a Dart import URI "doesn't exist" but the file is present and analyzes cleanly on its own, check `bytes.decode('utf-8')` first.
- Also deleted stale `fyp_jaspr_web/.dart_tool/build/asset_graph.json` and ran `dart pub get --offline` (resolves root workspace config); neither fixed the URI error — encoding was the cause. All diagnostic probe files removed. The remaining info-level lint (`curly_braces_in_flow_control_structures` at widget line ~1072) was then fixed by wrapping the `if (mounted) setState(...)` body in braces.
