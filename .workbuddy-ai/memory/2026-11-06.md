## Fix: auth pages / sign-in "run two times" (double execution + double navigation)

Root cause (measured in headless Chromium, not guessed): `announceReady()` was
called TWICE inside `initialize()` in `tool/auth_client.js`, so the
`sitewise:auth-ready` event fired **2x on every page load** (`/login`, `/`,
`/signup`, `/auth/callback`). On top of that, several overlapping async paths
(OAuth callback `complete()`, `SIGNED_OUT`, re-mounted `@client` widgets) each
called `location.assign(...)`, which could start a second document load.

Changes (all in `fyp_jaspr_web/`):
- `tool/auth_client.js`
  - Added `navigate(url)` single-flight helper (`navigationStarted` latch) using
    `location.replace()` instead of `location.assign()`. All 6 auth redirects now
    go through it. `replace()` keeps transient `/login` and `/auth/callback`
    documents out of history, so Back cannot re-run the sign-in flow.
  - `initialize()` is now single-flight (`initInFlight`); the retry loop AND the
    background recovery poller can no longer create two Supabase clients /
    two `onAuthStateChange` subscriptions.
  - `announceReady()` is still re-runnable for DOM updates (late config
    recovery) but dispatches `sitewise:auth-ready` exactly once (`readyAnnounced`).
  - `complete()` is memoized (`completionInFlight` + module-level `doComplete`),
    so concurrent/duplicate calls share one PKCE exchange + profile fetch.
    A rejection clears the slot to allow a genuine retry.
- `lib/pages/auth_callback_page.dart` / `lib/pages/staff_mfa_page.dart`:
  static per-document latches (`_started` / `_initializing`) in `initState()`
  so hydration re-mounts cannot start a second completion/enrollment.
- Rebuilt `web/auth_bundle.js` (`npm run build-auth`) and ran `jaspr build`.

Verification (Chromium, port 8090 dev server + 8091 built server):
- `sitewise:auth-ready`: 2 -> **1** on `/login`, `/signup`, `/`, `/auth/callback`;
  exactly 1 main-frame navigation per page; 0 page errors.
- Triple concurrent `complete()` calls share one execution (same rejection
  object, 0 duplicate `/api/v1/auth/me` requests); two concurrent `signout()`
  calls produce ONE navigation.
- `dart analyze lib`: clean. Probes: `probe_backend_integration.js` 43/43,
  `probe_ssr_mpa.js` 27/27, social/staff/auth-flows/login PASS.
- `verify_backend_integration.js` still fails its `.pcard` fixture step: that
  fixture stubs `auth_bundle.js` and never sets the SSR `sitewise_session`
  cookie, so `/entrepreneur/explore` 302s to `/login?next=`. PRE-EXISTING,
  unrelated to this fix (the fixture touches no changed code).

Gotcha reconfirmed: `jaspr build` invalidates a running `jaspr serve` dev
daemon (it replaced `build/jaspr` -> port 8090 answered 500). Restored via
`.\serve`, whose scoped cleanup killed the orphaned dart chain (PID 33092 / 26384)
and rebuilt DDC assets. Launcher + backend on 8000 are healthy again.
