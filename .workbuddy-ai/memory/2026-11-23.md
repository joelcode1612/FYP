### Mobile verification (§9) — how to reproduce
- `CqDevelopmentAccess.permitted()` needs: debug build, `SITEWISE_ISOLATED_CQ_TEST`, non-empty
  bearer, and `API_BASE_URL == CQ_TEST_BASE` on loopback, port >1023, not 3080/5432/8000/8090.
- **`assets/config/sitewise_dev.json` overrides `--dart-define`.** `MobileRuntimeConfig.boolean`
  reads the asset first; the dart-define is only the fallback. `SITEWISE_DEV_AUTH_BYPASS` ships
  `"false"`, so the bypass must be set in the asset (tracked file — record SHA, edit, revert,
  re-verify). Bypass also needs `kDebugMode`, so release builds are safe.
- `adb reverse tcp:18090 tcp:18090` + server on a fixed port; app reaches it as 127.0.0.1.
- Driving: `adb shell uiautomator dump` → parse `content-desc` + `bounds` → `input tap`. Flutter
  renders text into `content-desc`, not `text`.
- **Hazard:** an unlock swipe can traverse the app's controls as the page changes beneath the
  pointer, silently tapping Start *and* consent. Unlock BEFORE launching, or accept that the
  consent is an artifact of synthetic touch (record it as simulated, never as genuine).
