- Root cause: SQLAlchemy 2.1.9 `text()` does NOT substitute a `:name` bind param when immediately followed by `::` (PG cast). `:psf_price::numeric` stayed raw in compiled SQL while WHEN-clause tokens (followed by space) compiled to `%(psf_price)s`; psycopg2 sent literal `:` → `ProgrammingError: syntax error at or near ":"`. Empirically confirmed via compile test.
- Fix: `fyp_property_repository.py` psf clause now uses `ROUND(CAST(:psf_price AS numeric) / CAST(:psf_size AS numeric), 2)` with explanatory comment. Repo-wide grep `:\w+::` in backend/src: only other hit is line 660 column cast (no bind param, safe).
- Verified: real `update_owner_listing(11910, {rental_price: 3200.0, size_sqft: 326.0}, commit=False)` against Final_Location_Analysis inside explicitly ROLLED-BACK transaction — UPDATE executed, psf=9.82 (=round(3200/326,2)), no persistence.

## 360° frame upload 503 on resume — fixed (property 11910 / session ea5e4def…) — 2026-11-25

**Root cause (measured against the live bucket):** Supabase Storage refuses to mint a signed
upload token for a path that already holds an object unless `x-upsert: true` is sent. Without
it the API answers `status=409 code=Duplicate message="The resource already exists"` (some
proxy logs render it as 400). `capture_storage.signed_upload_url()` caught every exception and
re-raised `CaptureStorageUnavailable`, and `issue_upload_urls` wrapped the whole target loop in
one try → **one already-stored frame 503'd the entire batch of 38**.

Affected session state: 19 objects in `frames/` (1–19), **0** `fyp.capture_frames` rows,
panorama row present (pending, unpublished), session `completed`. So the objects were uploaded
but never confirmed — a pure resume case, not corrupt data.

**SDK capability check:** `storage3` **2.34.1** supports
`create_signed_upload_url(path, options=CreateSignedUploadUrlOptions(upsert="true"))`; the
option is `upsert: str` (not bool) and becomes the `x-upsert` header. Verified live: upsert
signing succeeds for an occupied path.

**Backend**
- `services/capture_storage.py`: `signed_upload_url(..., upsert=False)`; new
  `ObjectAlreadyStored` (duplicate = resume signal, not outage); `_is_duplicate()` matches
  `Duplicate`/`KeyAlreadyExists` or 400/409 + "already exists"; `_log_refusal()` logs
  `status/code/message` only (never the URL/token); duplicates log at INFO because
  `core/logging.py` is `basicConfig(level=INFO)`.
- `api/v1/capture_360.py`:
  - `UploadUrlRequest.overwrite: list[int]` — explicit replacement only.
  - `issue_upload_urls` signs per target (create-only first; the storage API's own Duplicate
    is the existence check, so no TOCTOU) → `alreadyStored: true` + `uploadUrl: null` for
    occupied paths. Genuine outage still 503.
  - `FrameConfirm.uploaded: bool = True`; `uploaded=false` forces the stored-bytes download +
    checksum comparison before a row is written (resume never blindly trusts an old object).
  - `issue_panorama_upload_url(overwrite=False)` + `_require_replaceable_panorama()` — an
    approved or **published** panorama can never be replaced (guard runs BEFORE the upsert URL,
    because `confirm_device_panorama` checks only after bytes are written).
- Verified offline with mock doubles (7 cases) + live signing probe on the affected session.

**Mobile** `backend_capture_coordinator.dart`
- `_issueUploadUrls(..., overwrite)`; `_alreadyStored()`; `_putWithRetries()` (expiry refresh +
  network retry, skippable when the object is stored); `_uploadOne` confirms without PUT, and on
  a *replaceable* 409 (checksum / not-reached-storage) requests an upsert URL once, then
  re-uploads. Authorization/cancellation/review conflicts are never overwritten.
- `_backupFrames`: per-batch permission failure and per-target failure are collected, not fatal;
  the queue continues, then one friendly `BackendHandoffFailure` reports how many remain.
  `processed` now starts at `total - toUpload - toRepair` (repairs are counted only when they
  succeed). `_repairConfirmed` sends `uploaded: false`.
- `_friendlyFailure()` maps any `AppFailure` to a person-readable sentence (401/403, network,
  backend conflict) and logs the technical cause; raw Supabase/HTTP text never reaches the UI.

cluster on 5433 is not running on this machine.
