## Capture-38 crash / frame 409 investigation (joel, uncommitted)
- Session `07f5cb65-…` has 44 expected frames, 23 confirmed, and an orphan `31.jpg` object (3.74 MB) in `property-panoramas`; 409 comes from `POST /frames` refusing metadata because the object is absent or its bytes do not match the supplied checksum. The client already retries checksum conflicts once with an authorized overwrite; an interrupted retry leaves the orphan.
- Crash at ~38 is native memory growth, not the 409: `DartCvOverlapProbe` disposed Mats but never the `VecKeyPoint` vectors, descriptor Mats, or `cv.Mat.empty()` masks, and every captured frame queued another unawaited quality analysis. At 44 frames that accumulates unbounded native/Dart memory.
- Fix: overlap probe now decodes at `IMREAD_REDUCED_COLOR_4`, explicitly disposes keypoints/descriptors/masks, and `SphereCaptureController` serialises quality analysis through one in-flight + one pending job (`_QualityJob`), releasing the rest. Also disposed the inline empty mask in `sphere_frame_registration.dart`.
- Analyzer clean on the touched Dart files; no tests/builds/commit.
