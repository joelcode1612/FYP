# 2026-10-15 — ARCore Kotlin build errors fixed (untitled2_360_capture_advanced)

User hit 3 Kotlin compile errors running `untitled2_360_capture_advanced`
(**a separate project from the FYP workspace**, sibling directory under
`AndroidStudioProjects`). Depends on `com.google.ar:core:1.52.0`.

## Root cause 1+2 — `com.google.ar.core.Size` does not exist
`ArCoreSessionHost.kt:491-492` did:
```kotlin
val size = intrinsics.imageDimensions
out["imageWidth"] = size.width      // Unresolved reference 'width'
out["imageHeight"] = size.height    // Unresolved reference 'height'
```

**Proven by inspecting the actual SDK**, not guessed: extracted
`core-1.52.0.aar` → `classes.jar` and ran
`javap -cp classes.jar -public com.google.ar.core.Size` → **"class not found"**.
`CameraIntrinsics` in 1.52.0 is:
```
float[] getFocalLength();      float[] getPrincipalPoint();      int[] getImageDimensions();
```
All three return **arrays**, never objects. The code already indexed the first
two with `[0]`/`[1]` correctly; only image dimensions was written as an object.

**Fix:** `val dimensions = intrinsics.imageDimensions` then
`dimensions[0]` / `dimensions[1]`.

**Order confirmed from Google's official ARCore docs:** *"Returns a `int[2]`
containing the image dimensions. The order of values is `{width, height}`."*
So `[0]`=width, `[1]`=height.

## Root cause 3 — `val` reassigned
`SceneRenderer.kt:73` declared `private val scratch: FloatBuffer` but
`drawPlane` reallocates it to grow: `scratch = createFloatBuffer(...)` (line
137). Changed to `private var scratch`. Trivial, low-risk.

## Verification method that mattered
Could **not** run `flutter build apk` — my shell dies at the very first step
(`git log`) with `All pipe instances are busy` (errno 231), the same Windows
named-pipe exhaustion that blocks `jaspr serve`, `dart test` and
`flutter analyze` on this machine. Gradle never even started.

Instead: **audited every ARCore type referenced in the two files against the
compiled jar.** All 12 types resolve — Anchor, ArCoreApk, Camera, Config,
Frame, HitResult, Plane, Pose, Session, Trackable, TrackingState, and `Size`.
`Size` was the **only** miss, and the build log reported exactly 2 errors (its
two member accesses) + 1 val/var error. Count and identity match exactly, so
all 3 errors are accounted for with none left over.

Project-wide sweep for remaining `arcore...Size` references → none (the
`viewportSize()` hits are a local method returning `Pair<Float,Float>`).

## Caveat on the fix's scope
Only `.width`/`.height` on `intrinsics.imageDimensions` were wrong. The same
syntax at lines 704/705, 755/756, 811/812 uses `image.width`/`image.height` on
a **different** object and compiled fine — Kotlin reports every unresolved
reference in a file, so their absence from the log proves they resolve. Do not
"fix" those.
