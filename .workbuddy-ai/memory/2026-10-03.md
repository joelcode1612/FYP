# 2026-10-03 — Mobile pre-login refactor + integration

## Done
Refactored the monolithic `sitewise_prelogin_mobile_flow.dart` (783 lines, from Downloads)
into a layered multi-file mobile onboarding + auth feature and integrated it into Sitewise.

## Architecture decisions (read before touching onboarding/auth)
- The project has **no Supabase and no pre-existing auth layer** (`AppConfig.supabaseUrl` is
  empty; landing "Log In" was only a demo role picker). Added ONE minimal auth layer in the
  existing style: `domain/repositories/auth_repository.dart` (contract),
  `data/repositories/auth_repository_impl.dart` (demo/local, backed by `DemoData.users`,
  persists session to `<appDocs>/sitewise/state/session.json`),
  `application/services/auth_service.dart`. Swap the impl for Supabase later; UI stays.
- **No shared_preferences dependency.** Onboarding flag uses the project's existing
  file-based pattern (`path_provider` + `dart:io` + JSON) behind
  `data/datasources/local/onboarding_local_data_source.dart`
  (`FileOnboardingLocalDataSource` + `InMemoryOnboardingLocalDataSource` for tests).
  Flag key: `sitewise_mobile_onboarding_completed`.
- Routing is the custom `AppRoutes.onGenerateRoute` switch (no go_router). `'/'` is now the
  **startup gate** (`AppStartGate`); public landing moved to `'/landing'`; new routes
  `'/onboarding'` and `'/auth'` (mobile-only).
- `ServiceLocator.onboardingRepo` and `ServiceLocator.auth` are intentionally **non-final**
  so tests inject `InMemoryOnboardingLocalDataSource` / fake auth repos.
- Web vs Mobile: `PresentationEnvironmentResolver` (width >= 1024 => web). Mobile gets
  onboarding/auth; web still starts at the public landing. Onboarding is never imported by
  the web tree.
- Logout was added to the shared `SitewiseRoleMenu` popup: clears the session and routes to
  `/auth` (mobile) or `/landing` (web). Onboarding is NOT shown again after logout.
- Onboarding = 5 stages (indicator fixed from 3 dots); auth is NOT part of the indicator.
  Completion is written only on Get Started / Log In / Sign Up / Skip — never on swipe.

## Environment caveat #2 — how to analyze when `dart analyze` is broken
`dart analyze` / `flutter analyze` still fail with "CreateFile failed 231 / All pipe instances
are busy" (Windows pipe pool exhausted; Dart's Process.start cannot create pipes).
`dart format` still works and parses everything (0 syntax errors across 187 files).

**Workaround that DOES work**: drive the analysis server directly from Python (Python's
subprocess pipes are fine). Scripts written to
`C:\Users\Lenovo\AppData\Local\Temp\sw_lsp.py` (LSP protocol) and `sw_legacy.py`
(legacy `--protocol=analyzer`). Spawn:
`dartaotruntime.exe <dart-sdk>/bin/snapshots/analysis_server_aot.dart.snapshot
--dart-sdk=<sdk> --packages=<repo>/.dart_tool/package_config.json`.
Gotcha: the analysis server writes verbose logs to stderr — if you don't drain stderr on a
thread, the pipe buffer fills and the server deadlocks (symptom: zero output).
LSP mode only publishes diagnostics for `didOpen` files, so coverage is partial; the legacy
protocol with `analysis.setGeneralSubscriptions:["ERRORS"]` gives project-wide errors.

Pipeline validated with a deliberate probe error (detected correctly, then removed).
Final result: **0 errors / 0 warnings / 0 infos across lib + test (187 files)**.

This workaround is saved as a reusable skill:
`~/.workbuddy-ai/skills/dart-analyze-lsp/` (SKILL.md + scripts/analyze_lsp.py).

`flutter test` still cannot run at all (the Flutter CLI itself dies on the git version
check), so the widget tests are updated but unverified on this machine.

Lint fixes applied from the analyzer output: `OnboardingController` now uses a public
`onboarding` field + `{required this.onboarding}`; `InMemoryOnboardingLocalDataSource`
exposes `bool completed` + `{this.completed = false}`; braces added in
`MobilePropertyFilter.matches`.

used for **layout/rhythm only**, never content or branding.
