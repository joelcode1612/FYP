## serve.ps1 TIME_WAIT fix + stale build cache (2026-11-03)

- User's `.\serve` failed: `PID 0 (Idle) owns socket(s) 8090 [TimeWait]` ->
  "not a Dart process, refusing". Root cause: TIME_WAIT sockets are remnants
  of closed connections with OwningProcess 0; the port scan kept all
  non-Listen states (intended for CLOSE_WAIT orphans) so PID 0 hit the
  not-a-Dart guard and exited 1.
- Fix: both scan sites in serve.ps1 now require
  `State -ne 'TimeWait' -and OwningProcess -ne 0`. Validated with -CheckOnly
  ("ports free"). CLOSE_WAIT orphans are still caught by design.
- Second blocker after that: build failure `AssetNotFoundException:
  auth_navbar.ddc` — stale `.dart_tool/build` cache after the user added
  files (analyzer showed current code clean). Fixed by deleting
  `.dart_tool/build`, then rebuild served fine.
- Tooling note: PowerShell-background serve runs fail opaquely (truncated
  output); the reliable pattern is Bash background
  `env -u HTTP_PROXY... dart run jaspr_cli:jaspr serve > tool/_diag/serve.log`.
  serve.ps1 is unsigned — needs ExecutionPolicy Bypass when run from tooling
  (user's own terminal runs it fine).
- End state: API :3001 healthy, web :8090 serving, auth snapshot
  configured:true on /login and /signup, Google button enabled.
