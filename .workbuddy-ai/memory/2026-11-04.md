## "Error: Failed to fetch" on signup — root cause confirmed

- Screenshot showed signup with red "Error: Failed to fetch" + Google disabled
  + "Social sign-up is not configured in this deployment".
- Mechanism: `tool/auth_client.js` `ready` promise does
  `fetch(http://localhost:3001/api/config)` at page load. When the Express API
  is down, the browser fetch throws TypeError "Failed to fetch"; the catch sets
  `state.error = 'Failed to fetch'` (rendered in the card alert) and keeps
  `configured=false` (Google disabled + social note).
- Verified at 13:20: :3001 DOWN, :8090 DOWN. Started both (npm run start:app
  via PowerShell bg; .\serve.ps1 via PowerShell bg with ExecutionPolicy
  Bypass). Dev server needed ~2 min for initial web-compiler build.
- After restart: `/api/config` -> configured:true, `/api/health` -> ok:true;
  CORS preflight from Origin http://localhost:8090 -> 204 with correct
  allow-origin/headers; browser check on /signup -> snapshot
  {"configured":true,"error":""}, Google enabled, no "Failed to fetch" text,
  no error alerts. Only failed network request = Dart dev SSE handler
  (ERR_ABORTED, harmless).
- Standing fix: both servers must run in the USER'S terminal windows; session
  background tasks die. Refresh the tab after starting the API.
