# 2026-10-08 (later) — Fixed the Chrome / web build failure

## Root cause (empirically established, not guessed)
Compiling for web (`flutter run -d chrome`) failed with ~80 errors in `dartcv4-2.2.2`:
`Error: Dart library 'dart:ffi' is not available on this platform.`

`opencv_dart` → `dartcv4` uses ffigen-generated `dart:ffi` bindings. **`dart:ffi` is
native-only** — a browser has no C/C++ runtime to bind to. No version pin fixes it
(1.1.8 / 2.2.1+4 / 2.2.2 all use FFI identically); there is no OpenCV-for-web.

The companion error `Only JS interop members may be 'external'` is a **downstream symptom**
of the same cause, not a second bug.

## Verified by direct experiment
- `dart compile js` on a file importing `dart:io` → **compiles fine** (136 KB JS). So
  `dart:io` is NOT a web blocker; `capture_frame_store`, `onboarding_local_data_source`,
  `auth_repository_impl`, `pano_bytes_io` are all safe.
- `dart compile js` on a file importing `dart:ffi` → hard error. Only FFI blocks web.
- The codebase **already had** the right pattern: `core/utils/pano_bytes.dart`
  (`import 'pano_bytes_stub.dart' if (dart.library.io) 'pano_bytes_io.dart' as impl;`).

## Fix applied (in the EXPERIMENT project only)
Single reachable FFI import existed (`opencv_panorama_stitcher.dart:3`), constructed in one
place (`service_locator.dart:56`). Split it three ways, mirroring the `pano_bytes` pattern:
- `panorama_stitcher_native.dart` — OpenCV impl, moved **byte-identical**
- `panorama_stitcher_stub.dart` — `UnavailablePanoramaStitcher`, honest `StitchResult.failure`
- `panorama_stitcher_platform.dart` — conditional import + `createPanoramaStitcher()`
- deleted `opencv_panorama_stitcher.dart`; `service_locator` now calls the factory

Commit `6526b90`. Original FYP project untouched (no `lib/` changes).

## Proof it works
Compiled the real seam to JS and inspected the bundle:
- stub strings **present** (`unavailable in the browser`, `Checking platform support`)
- OpenCV strings **absent** (0 hits for `stitchAsync`, `Preparing images`, `Stitching failed`)
- **0** hits for `dart:ffi` / `opencv` / `dartcv`

## Durable convention
**Never import `opencv_dart` outside `panorama_stitcher_native.dart`.** Reaching it from any
file on the web path breaks the JS build. Always go through
`panorama_stitcher_platform.dart`.

## Known runtime caveats on web (compile OK, but)
- `ar_flutter_plugin` declares only `android` + `ios` → AR capture screens throw
  `MissingPluginException` at runtime on web (app still boots).
- `path_provider` has no web impl → session/onboarding persistence silently falls back to
  in-memory (every call is already wrapped in `try/catch`).

(`CreateFile failed 231`). The Python LSP analyzer ran but returned
