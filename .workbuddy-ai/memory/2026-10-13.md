**Fixed:** `_countMatching(keyword)` does a case-insensitive substring match.
`propertyType` is free text, not an enum, so categories legitimately overlap.

# 2026-10-13 (later) — Web icons aligned to the mobile tree

User: *"i see the web UI their icon is not same with the mobile so i want you copy
the icon from the mobile and change in the web"*.

## Root cause: Flutter's `Icons.*` is not one style
`Icons.foo_outlined` / `Icons.foo_rounded` / `Icons.foo` are three *different*
renderings, and the mobile tree uses all three:

| Flutter | Material Symbols | CSS |
|---|---|---|
| `Icons.foo_outlined` | Outlined family, FILL 0 | `.ms` (default) |
| `Icons.foo_rounded` | **Rounded** family, FILL 0 | `.ms--rounded` |
| `Icons.foo` | Outlined family, **FILL 1** | `.ms--fill` |

The web loaded **only Material Symbols Outlined at FILL 0**, so every `_rounded`
and every filled icon rendered wrong.

## Changes
- `lib/main.server.dart` — added the **Material Symbols Rounded** font link.
  (Note: `web/index.html` no longer exists; the head links live in the Dart
  `Document`, so this is where fonts are declared now.)
- `web/styles.css` — added `.ms--fill` (FILL 1) and `.ms--rounded` (family
  override), placed *after* `.ms` so single-class overrides win.
- `lib/data/icon_variants.dart` — **new**. One table recording which icons need
  which variant, since the mobile tree is the source of truth:
  - filled: `threesixty`, `compare_arrows`, `bookmark`
  - rounded: `chevron_right`, `notifications`
- `lib/components/ui.dart` — `Icon` now resolves the variant from that table,
  with `filled`/`rounded` params to override per call site.
- `lib/data/navigation.dart` — **`group` → `people`**. Mobile uses
  `Icons.people_outline`; Material Symbols renders `group` and `people` as
  genuinely different glyphs.

## Near-miss worth remembering
I almost added `groups` to the *rounded* set. Checking the mobile landing content
showed it uses `Icons.groups_outlined`, so the web's `groups` was already correct.
**Verify the actual `Icons.*` name in `fyp_mobile_app` before "fixing" a variant.**
